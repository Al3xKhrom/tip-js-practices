**Исправление эксперимента 2:**
Исходная причина: в стрелочной функции с фигурными скобками был пропущен `return`, из-за чего изначальный результат был `undefined`.
Исправление: добавлено ключевое слово `return` перед `value * value`. После этого функция корректно возвращает результат вычисления, и итоговый результат стал `16`.

*   **Проверка ID:** Реализована строгая проверка на то, что `id` является числом, а также положительным безопасным целым (`Number.isSafeInteger(id)` и `id > 0`). Отсекаются дробные значения, `NaN`, `Infinity` и строки.

## Задание 3

В файл `src/task-service.js` добавлены четыре функции для извлечения данных и расчета статистики на основе массива задач:
*   **`findTaskById(tasks, id)`**: Поиск задачи по уникальному идентификатору с использованием метода `find`. Применяется строгое сравнение, что гарантирует возврат `undefined` при несовпадении типов (например, при поиске числового ID по строке). Возвращает сам найденный объект.
*   **`getPendingTasks(tasks)`**: Формирование списка невыполненных задач. Использует метод `filter` для создания нового массива объектов, у которых `completed === false`. Порядок исходных записей сохраняется.
*   **`getTaskTitles(tasks)`**: Извлечение названий. Использует метод `map` для создания нового массива, состоящего исключительно из строк с названиями всех переданных задач.
*   **`getTaskStats(tasks)`**: Расчет сводной статистики. Вычисляет общее количество задач (`total`), количество выполненных (`completed`) и оставшихся (`pending`). Также рассчитывает процент выполнения (`progress`) в виде точного числа без округления. Предусмотрена обработка пустого списка: если задач нет, все поля, включая `progress`, равны `0`, что исключает ошибку деления на ноль.

## Задание 4

В файл `src/task-service.js` добавлены четыре функции для модификации списка задач. Работа с данными реализована по принципам строгой иммутабельности:
*   **`addTask(tasks, id, title, priority)`**: Добавляет новую задачу в конец массива. Внутри переиспользуется функция `createTask` для валидации полей и создания объекта. Реализована проверка на уникальность `id`: если задача с таким идентификатором уже существует, возвращается ошибка. Возвращает новый массив, созданный через spread-синтаксис.
*   **`setTaskCompleted(tasks, id, completed)`**: Изменяет статус выполнения задачи. Аргумент `completed` принимает строго логические значения `true` или `false` (без неявного приведения типов). Применяется метод `map`, который при совпадении `id` создает новый объект задачи с обновленным полем, сохраняя ссылки на неизмененные записи.
*   **`renameTask(tasks, id, title)`**: Изменяет название задачи. Название проходит строгую валидацию и нормализацию (через `trim()`) по тем же правилам, что и при создании. Как и при смене статуса, используется метод `map` для возврата нового массива с обновленным объектом.
*   **`removeTask(tasks, id)`**: Удаляет задачу по `id` с помощью метода `filter`. Порядок оставшихся элементов и их идентификаторы не изменяются. Если задача с указанным `id` отсутствует, возвращается стандартная ошибка.

**Общие архитектурные решения:**
Все функции соответствуют единому контракту: при успехе возвращается `{ ok: true, tasks: <новый массив> }`, при провале — `{ ok: false, error: "Описание" }`. Прямые мутации (использование `push`, `splice` или переназначение свойств входных объектов) полностью исключены. Для сокращения дублирования кода проверки `id` и `title` вынесены во внутренние вспомогательные функции модуля.
