## Компоненты, состояние, события

В `App.jsx` хранятся `tasks` (полный массив), `filters` (значения четырёх фильтров), `editingId` (идентификатор редактируемой записи), `sortMode` (режим дополнительной сортировки), `announcement` (сообщение пользователю). Компонент `TaskForm` самостоятельно хранит черновик `draft`, ошибки полей `errors` и локальное сообщение `message`.

`App` передаёт данные вниз через `props`, а дочерние компоненты вызывают переданные обработчики `onSave`, `onCancel`, `onToggle`, `onEdit`, `onDelete`, `onChange`. Изменением массива задач занимается только `App`, а предметные операции выделены в чистые функции `task-service.js`. Прямого редактирования DOM через `innerHTML` или `querySelector` для управления интерфейсом нет.

Производные данные **не хранятся в дополнительном состоянии**: `visibleTasks = selectTasks(tasks, filters)` вычисляется из актуальных задач и фильтров, `displayedTasks = sortTasks(visibleTasks, sortMode)` — из видимой выборки, `stats = getTaskStats(tasks)` — из **всего** массива, `editingTask` — по `editingId`. Поэтому список и статистика согласованы после каждого действия без `useEffect`.

Массивы и записи обновляются **неизменяемо**: `map` для редактирования и переключения статуса, `filter` для удаления, `[...tasks, newTask]` для добавления. Идентификаторы задач имеют пропуски; поэтому используется `task.id`, а не индекс массива. При создании следующий id считается как максимум **полного актуального массива** плюс 1 (для пустого массива — 1), внутри чистой функциональной операции `setTasks(previous => ...)`.

Ключи карточек: `key={task.id}`. Форма получает `key={editingId ?? 'new'}`: при переключении между редактируемыми записями React пересоздаёт форму и сбрасывает черновик. При отмене редактирования массив задач не меняется. Подтверждение удаления `window.confirm()` вызывается **до** `setTasks`, чтобы побочные эффекты не попадали в функцию обновления состояния в режиме `StrictMode`.

Валидация выполняется до сохранения. Требования: строковое название длиной 1–100 символов после `trim`, приоритет `low`/`medium`/`high`, существующая категория (строковый id из HTML `select` преобразуется в целое число). Ошибки всех полей выводятся одновременно, пользовательский ввод при ошибке сохраняется. При успешном создании форма очищается. При редактировании поля `id` и `completed` сохраняются. Кнопки и поля имеют подписи, `aria-invalid`, `aria-describedby`, сообщения `role="status"`/`role="alert"`, видимый фокус, управление с клавиатуры.

Фильтры поиска, статуса, приоритета, категории одновременно объединяются по логике **И**. Поиск не зависит от регистра и крайних пробелов. Сброс устанавливает четыре пустые строки (не возвращает стартовый фильтр варианта). Сортировка не изменяет `tasks`, а создаёт новый массив только для вывода. В `TaskList` различаются «нет задач вообще» и «нет совпадений с фильтрами».
