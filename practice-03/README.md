| **1** | `querySelector` вернет `null`, а `querySelectorAll` — пустой массив. | `null` и пустой `NodeList` (длина 0). | При поиске отсутствующего элемента `querySelector` возвращает `null`, и обращение к его свойствам вызовет ошибку (`TypeError`). `querySelectorAll` возвращает пустую коллекцию `NodeList`, у которой безопасно можно прочитать свойство `length` (оно равно `0`). |

Для математических операций или строгого сравнения их необходимо явно преобразовывать в числа (например, через `Number()`). |
| **3** | Длина `initialItems` не изменится, а новый поиск покажет больше элементов. | `initialItems.length` осталась прежней. Она фиксирует состояние DOM на момент вызова и не обновляется при добавлении новых узлов. Чтобы получить актуальное количество, нужно вызвать `querySelectorAll` заново. |
| **4** | Выведутся теги текстом, они не станут жирным шрифтом. | На экране отобразилась строка с тегами `<strong>...</strong>`. В DOM новый элемент не создался. | Свойство `textContent` записывает переданную строку как обычный текст, экранируя HTML-теги. Чтобы браузер отрендерил тег `<strong>` как HTML-элемент, нужно использовать свойство `innerHTML` (или создавать узел через `createElement`). |
| **5** | Событие пойдет сверху вниз, сработает на `span`, затем всплывет на кнопку. | Фазы: 1 (захват), 2 (цель - `span`), 3 (всплытие). `target` — это `span`, `currentTarget` — контейнер/кнопка. | Клик по вложенному элементу `span` инициирует проход события. `event.target` всегда указывает на самый глубокий элемент, по которому кликнули (`span`). `event.currentTarget` указывает на элемент, к которому привязан обработчик `addEventListener` (в процессе всплытия). |

**Ответ на вопрос из критерия готовности:**
*Почему обработчик контейнера может получить нажатие на вложенный элемент?*
Это происходит благодаря механизму **всплытия событий (Event Bubbling)**. Когда происходит клик по самому глубокому вложенному элементу (например, по `span` внутри кнопки), браузер сначала запускает обработчики на этом `span` (фаза цели). Затем событие начинает "всплывать" вверх по дереву DOM, поочередно запуская обработчики клика на его родителях (на `button`, затем на `div`-контейнере, `body` и так далее). Поэтому обработчик, "висящий" на контейнере, успешно ловит клики по всем элементам внутри него.

## Задание 3

В файле `main.js` реализована функция `handleTaskListClick` для обработки событий клика по списку задач с использованием паттерна делегирования.
**Реализованный алгоритм:**
1. **Захват элемента:** Через метод `closest` функция ищет ближайшую кнопку `button[data-action]`, игнорируя клики по пустым областям, тексту или заголовкам.
2. **Фильтрация действий:** Обрабатываются строго два действия: `toggle` и `delete`.
3. **Валидация идентификатора:** ID задачи считывается из `li[data-task-id]`, преобразуется в число через `Number` и проверяется на то, что это положительное безопасное целое число. Если идентификатор некорректен, операция прерывается с выводом понятного сообщения без повреждения состояния приложения.
4. **Взаимодействие с бизнес-логикой:** Изменение данных происходит исключительно через сервисы ПР2 (функции `setTaskCompleted` и `removeTask`). Статус выполнения (`completed`) берется из актуального массива через `findTaskById`, а не вычисляется на основе DOM (CSS-классов или текста кнопки). Прямое удаление узлов через `element.remove()` не используется.
5. **Обработка результата:** При ошибке (например, передаче отсутствующего ID) состояние `currentTasks` остается неизменным, выводится сообщение об отказе. В случае успеха новый массив `result.tasks` сохраняется в состояние, интерфейс полностью перерисовывается для соответствия новым данным, ошибки очищаются, и вызывается `restoreTaskFocus(id, action)`.

**Результаты проверок:**
*   Нажатие на вложенную подпись кнопки (тег `span`) корректно перехватывается благодаря `closest`.
*   Двойное последовательное переключение статуса корректно инвертирует значение и обновляет DOM.
*   Удаление записи полностью убирает её из данных и интерфейса при повторной отрисовке.
*   Действия на одну задачу (например, `id = 4`) изменяют ровно одну нужную запись, не затрагивая остальные.

*   В обоих случаях последующий корректный выбор фильтра успешно пересоздает карточки из нетронутого актуального массива и очищает возможные сообщения об ошибках. Эксперимент проведен исключительно инструментами браузера без изменения исходного HTML-файла или массива.
