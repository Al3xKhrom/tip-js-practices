## Задание 5

В файле `task-storage.js` реализован модуль локального хранения данных, включающий четыре функции: `isValidTaskList`, `loadTasks`, `saveTasks` и `removeSavedTasks`.

**Реализованный алгоритм:**

1. **Проверка массива (`isValidTaskList`):** Проверяется, что передан массив задач. Для каждой записи проверяются положительный безопасный целочисленный `id`, уникальность идентификатора, нормализованное название длиной от 1 до 100 символов, логический тип `completed` и приоритет `low`, `medium` или `high`. При одной ошибочной записи отклоняется весь массив.
2. **Загрузка (`loadTasks`):** Создаётся независимая копия исходного набора. Если ключ отсутствует, возвращается `source: "initial"`. Если запись присутствует, JSON разбирается, проверяется версия `1` и схема задач. Корректные данные возвращаются с `source: "storage"`.
3. **Восстановление после ошибки:** Если чтение вызывает исключение, JSON повреждён, версия неизвестна или задачи не соответствуют схеме, функция возвращает `{ ok: false, source: "fallback", tasks: ..., error: "..." }`. В качестве задач используется новая копия исходного набора.
4. **Сохранение (`saveTasks`):** Данные проверяются до записи. При успехе создаётся JSON-объект `{ version: 1, tasks }`, который сохраняется под переданным ключом. Некорректные списки не записываются.
5. **Удаление (`removeSavedTasks`):** Удаляется только указанный ключ через `storage.removeItem(key)`, остальные записи сохраняются.
6. **Обработка исключений:** Операции чтения, записи и удаления выполняются внутри `try/catch`, поэтому ошибки хранилища возвращаются в виде объекта результата, а не выбрасываются наружу.

**Результаты проверок:**

В файле `main.js` реализованы функции `setFormMode(id = null)` и `handleFormSubmit(event)`, обеспечивающие создание и редактирование задач через одну HTML-форму.

**Переключение режимов формы (`setFormMode`)**

- При `setFormMode(null)` устанавливается `editingId = null`, очищаются поля и сообщения об ошибках, включается поле ID, устанавливаются заголовок «Добавление задачи» и кнопка «Добавить задачу». Кнопка отмены скрывается, а фокус переводится в поле ID.
- При `setFormMode(id)` через `findTaskById` находится актуальная задача. Форма заполняется её `id`, `title` и `priority`; ID блокируется, чтобы его нельзя было изменить. Заголовок меняется на «Редактирование задачи», кнопка — на «Сохранить изменения», появляется кнопка отмены. Фокус переводится в поле названия.
- Если задача отсутствует, отображается сообщение «Задача с ID ... не найдена», а текущий режим формы не меняется.

**Обработка отправки формы (`handleFormSubmit`)**

1. Через `event.preventDefault()` отменяется стандартная отправка формы.

## Дополнительное задание вариант А

В рамках дополнительного задания реализовано автоматическое сохранение незавершённых полей формы создания задачи с последующим восстановлением после перезагрузки страницы.
Для реализации использовался `localStorage`. Логика черновика добавлена в файл `main.js` без изменения структуры существующих задач и сервисных функций.

**Реализованные функции**

- **`readDraftFields()`** — получает текущие значения `id`, `title` и `priority` из HTML-формы в строковом виде.
- **`saveFormDraft()`** — сохраняет незавершённые поля при вводе данных пользователем. В режиме редактирования сохранение черновика не выполняется.
- **`loadFormDraft()`** — считывает JSON из отдельного ключа `localStorage`, проверяет версию и структуру данных. Повреждённые записи отклоняются.
- **`restoreFormDraft()`** — восстанавливает значения полей при запуске приложения в режиме создания.
- **`removeFormDraft()`** — удаляет черновик после успешного добавления задачи или явной очистки формы.

**Организация хранения**

Для черновика используются отдельные ключи:

- Общий набор: `tip-js-practice-04:draft:demo`.
- Индивидуальный вариант: `tip-js-practice-04:draft:variant`.

Данные черновика записываются в формате JSON:

```json
{
  "version": 1,
  "fields": {
    "id": "75",
    "title": "Подготовить командный прототип",
    "priority": "high"
  }
}
```

Черновик содержит только поля формы и не является созданной задачей. Массив `currentTasks` при сохранении черновика не изменяется.

**Особенности реализации**

Автоматическое сохранение выполняется при событии `input` и изменении приоритета через `change`.

При переключении в режим редактирования черновик не подставляется в поля существующей задачи и не перезаписывается. После отмены редактирования пользователь может продолжить заполнение сохранённого черновика.

После успешного добавления новой задачи черновик удаляется из `localStorage`.

Для явной очистки формы создана кнопка «Очистить черновик», которая удаляет соответствующий ключ и сбрасывает поля без изменения списка задач.

Кнопка общего сброса также удаляет черновик текущего набора, не затрагивая данные другого набора.

После обновления страницы ожидается предупреждение о повреждённом черновике. Приложение должно продолжить работу с сохранённым списком задач.
