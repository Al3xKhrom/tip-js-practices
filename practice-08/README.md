## Цель работы

Связать React с HTTP API: `useEffect`, зависимости и очистка эффекта, `AbortController`, предотвращение гонок, `async/await`, обработка ошибок GET и мутаций, повторная загрузка после записи. Вместо задач в локальном массиве источник данных — учебный HTTP-сервер ПР8 (аналог API ПР6). API хранит изменённый набор **в памяти процесса**; обычная перезагрузка страницы сохраняет данные, а перезапуск процесса API возвращает исходный набор. База данных в этой работе не используется.

Реализована функциональность CRUD через POST/PATCH/DELETE, четыре серверных фильтра, сообщения о загрузке/ошибке/пустом ответе, сохранение последнего успешного снимка, защитные механизмы для устаревших ответов и двойной отправки, сброс демонстрационного набора. При успешной записи повторяется GET с *актуальными* фильтрами.

Главный источник состояния — `useTaskData`. Снимок `{ tasks, categories, meta }` заменяется только после успешной загрузки; начальные массивы пусты. Список и `meta.total` описывают **последнюю серверную выборку**, а не все задачи сервера. Условия поиска и фильтров соединяются сервером через «И». Временное отсутствие совпадений — успешное состояние `ready`, а не HTTP-ошибка.

### Ключевые фрагменты реализованной логики

**Очистка эффекта и защита от устаревших результатов:**

```js
useEffect(() => {
  const controller = new AbortController();
  let isCurrent = true;
  setStatus('loading');
  setError(null);
  async function load() {
    try {
      const result = await api.loadInitialData(
        { q, completed, priority, categoryId },
        { signal: controller.signal }
      );
      if (!isCurrent || !mountedRef.current || controller.signal.aborted) return;
      setSnapshot(result);
      setStatus('ready');
      setLastUpdatedAt(new Date().toISOString());
    } catch (loadError) {
      if (!isCurrent || !mountedRef.current || controller.signal.aborted) return;
      if (loadError?.name === 'AbortError' || loadError?.kind === 'aborted') return;
      setError(loadError);
      setStatus('error');
    }
  }
  void load();
  return () => { isCurrent = false; controller.abort(); };
}, [api, q, completed, priority, categoryId, revision]);
```

**Синхронная блокировка и успешная запись:**

```js
if (!mountedRef.current || pendingRef.current) return false;
const controller = new AbortController();
pendingRef.current = true;
mutationControllerRef.current = controller;
setPending(true);
setMutationError(null);
try {
  await operation({ signal: controller.signal });
  if (!mountedRef.current || controller.signal.aborted) return false;
  setRevision(previous => previous + 1); // новый GET с текущими фильтрами
  return true;                            // POST/PATCH/DELETE уже подтверждён
} catch (mutationFailure) {
  if (!mountedRef.current || controller.signal.aborted) return false;
  setMutationError(mutationFailure);
  return false;
} finally {
  if (mutationControllerRef.current === controller) {
    mutationControllerRef.current = null;
    pendingRef.current = false;
    if (mountedRef.current) setPending(false);
  }
}
```

`AbortController` загрузки не используется для мутаций: изменение фильтра отменяет только предыдущий GET. При размонтировании отдельно отменяется текущая мутация. `pendingRef` блокирует повторную мутацию **ещё до рендера**, тогда как `pending` показывает состояние пользователю. `error` и `mutationError` существуют раздельно: неуспешное чтение после успешной записи не превращает подтверждённый POST в ошибку.

## Индивидуальное задание (Вариант №5)

**Начальное состояние:** фильтр `categoryId=1`; показаны задачи id **1, 7, 13**. Серверный запрос `GET /api/tasks?categoryId=1` возвращает 200, `meta.total=3`.

**Действие:** выбрать «Редактировать» у №1 «Изучить функции», сменить категорию «Учёба» на «Проект», сохранить. Форма передаёт `title`, `priority`, `categoryId: 2`; клиент отправляет `PATCH /api/tasks/1`, а затем GET с `categoryId=1`.

**Ожидаемый результат:** PATCH 200; обновлённый GET 200 с id `[7,13]`, `meta.total=2`; задача №1 отсутствует в текущем списке, но доступна в категории 2. Состояние `completed` при таком редактировании не меняется.

## Дополнительное задание

Добавлено `lastUpdatedAt`: время фиксируется только после подтверждённого GET и показывается через `<time dateTime=...>` в интерфейсе. Ошибка запроса и начало нового запроса не подменяют последнее успешное время. Проверить: открыть приложение → запомнить время → нажать «Обновить список» → время обновилось; при выключенном API успешное время не меняется.
